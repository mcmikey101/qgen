# qgen

## Цель проекта

Создание платформы для конвертации pdf/md/txt файлов с конспектами/статьями/образовательным материалом в пары вопрос-ответ и удобным импортированием в приложение Anki для более эффективного изучения и подготовки. 

## Этапы проекта

## Каркас frontend

### Основное назначение приложения и пользовательские экраны

Приложение предназначено для преобразования неструктурированного текста в отдельные карточки для более удобного изучения.
- Основной экран должен содержать список колод с карточками, поиск по названию и фильтр по тэгам.
Каждая колода содержит карточки, которые можно свободно просматривать, редактировать и удалять.
Колодами также можно делиться с другими пользователями
- Второй экран содержит список публичных колод, которыми делятся между собой пользователи, поиск по названию и тэгам
- Третий экран содержит конфигурацию Anki, показывает статус соединения, доступные колоды, управлене типами карточек
- Экран профиля пользователя с именем и аватаром

### Реализация при помощи React Typescript

## Backend, api и работа с бд

Инструменты: FastAPI, PostgreSQL, SQLAlchemy, pydantic

Текущая модель данных:
- `User`: `id`, уникальный `username`, хеш пароля `password_hash`, `created_at`.
- `RefreshSession`: идентификатор refresh-токена, пользователь, срок действия и признак отзыва.
- `Deck`: `id`, `owner_id`, `title`, `description`, `is_public`, `created_at`.
- `DeckTag`: `deck_id`, `value`.
- `Card`: `id`, `deck_id`, `front`, `back`, `created_at`.

Реализованные API-эндпоинты:
- `POST /decks` — создать колоду (`title`, `description`, `is_public`, `tags`).
- `GET /decks`, `GET /decks/{id}`, `PATCH /decks/{id}`, `DELETE /decks/{id}` — список, чтение, изменение и удаление своих колод.
- `GET/POST /decks/{id}/cards` — список карточек (поддерживает `search`, `skip`, `limit`) и ручное добавление.
- `PATCH/DELETE /cards/{id}` — изменение и удаление своей карточки.
- `POST /decks/{id}/generate` — генерация карточек из текста (`text`, необязательные `language` и `model`; пустой `model` использует модель из настроек backend).
- `POST /decks/{id}/generate-from-file` — извлечение текста и генерация из PDF, DOCX, MD или TXT (до 10 МБ).
- `GET /public/decks` — список публичных колод с фильтрами `search` и `tag`.
- `GET /public/decks/{id}`, `POST /public/decks/{id}/fork` — просмотр и копирование публичной колоды.
- `GET /decks/{id}/export/anki` — экспорт заметок в формате AnkiConnect.

### Аутентификация и авторизация

- `POST /auth/register` — регистрация по `username` и `password`. Пароль сохраняется в виде стойкого хеша Argon2.
- `POST /auth/login` — вход по имени пользователя и паролю.
- При регистрации и входе выдаются JWT access-токен (15 минут) и refresh-токен (7 дней). Сроки и секрет подписи задаются настройками `ACCESS_TOKEN_MINUTES`, `REFRESH_TOKEN_DAYS` и `JWT_SECRET`.
- `POST /auth/refresh` — обмен действующего refresh-токена на новую пару токенов. Refresh-токен одноразовый: после обмена предыдущий отзывается. Некорректные, просроченные и отозванные токены отклоняются.
- `POST /auth/logout` — отзыв refresh-токена текущей сессии. Требует access-токен и тело с `refresh_token`.
- `GET /auth/me` — получение текущего пользователя. Защищённые API-маршруты требуют заголовок `Authorization: Bearer <access_token>`.
- Маршруты работы с личными колодами и карточками проверяют владельца. Просмотр списка и карточки публичной колоды остаётся доступным без входа; копирование публичной колоды требует авторизации.
- Frontend содержит формы регистрации и входа, загружает профиль, обновляет access-токен по refresh-токену и очищает локальную сессию при выходе.

Frontend использует `VITE_API_URL` для адреса backend; по умолчанию это `http://localhost:8000`. Перед запуском установите Python-зависимости из `requirements.txt`. AnkiConnect вызывается браузером напрямую на локальном компьютере пользователя.
